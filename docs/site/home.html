01 / The idea

Same network. A different way to see it.

A conventional network multiplies inputs by weights, adds the results and applies an activation. Switch views to imagine those weights as color. The values and output stay the same.

What I'm imagining

Weights you can inspect as a field of color. A visual language for seeing a network's state and following what changes as information moves through it.

What this animation does

A small JavaScript forward pass with fixed example weights. Color represents the same scalar values. This is a teaching sketch, not a trained model or a native chromatic neural network.

Color alone adds no information. This display mapping is illustrative, not the project's scalar codec or its native RGBD encoding. The PyTorch experiments still use floating-point parameters, gradients and kernels.

02 / What exists in code

Four bytes. A finite color wheel.

The native Rust library stores actual canonical RGBD bytes. R, G and B locate a saturated color. D selects a finer position within that step. Operations use integer phases modulo 391,680.

Drag a phase to change the stored bytes. A sum past 391,679 wraps around the wheel. This JavaScript illustration follows the native encoding rules. It does not execute Rust in your browser.

01

Encode

A phase becomes a canonical RGB color and a D byte. Every element occupies 32 physical bits.

02

Compute

Add or multiply phase indices in Z/391680Z, then encode the result. Matrix contraction uses the same ring operations.

03

Inspect & save

Read the bytes, reshape a tensor or save a bounded file with a SHA-256 checksum. Python, C and the CLI call the Rust engine.

This is modular hue arithmetic. It does not reproduce general real-number arithmetic or physical paint and light mixing. Native autograd, GPU operators and neural training are not implemented.

03 / The questions I'm testing

An experiment with receipts.

There are several ideas here. Each needs its own comparison and its own evidence.

Native library

Can tensors store literal color tokens?

Yes. Rust owns the RGBD bytes and performs exact modular hue operations. The recorded operators were slower than equal-storage NumPy controls.

Read the native API ↗
Numerical research

Does color labeling improve learning?

The recorded equal-bit controls showed no task accuracy advantage from color labels alone. These experiments use floating-point PyTorch training.

See the measured results ↗
Cube experiments

What happens when information is distributed?

Color cubes and a software Fourier representation explore geometry, storage and reconstruction. The FFT remains floating point. Arbitrary missing-data recovery is not established.

04 / Try it and read the code

The library behind the picture.

The native wheel has no third-party runtime dependencies. Build it for the documented x86-64 Windows or Linux targets. The library, CLI and research dashboard run locally.

Python / native hue tensor

from chromatic_hue import HueEncoder

with HueEncoder.encode_phases([[1, 2], [3, 4]]) as a:
    with a @ a as result:
        print(result.phases())
        # (7, 10, 15, 22)
        print(result.storage_nbytes)
        # 16 bytes

The same four-byte storage per element. No hidden floating tensor in the native implementation.

05 / About me / Brad Clonan

Where there's a will,
there's a way.

I don't have the funds for expensive GPUs right now. So I'm getting creative with what I do have. A ton of RGB LEDs, some grit, and amateur soldering skills.

That's how I started building systems. Figure out what you can do with what you have. It's also how I've helped companies solve architectural problems without assuming a bigger budget is the answer.

Now my son and I are building the next experiment. The plan is to put the LEDs in a box with mounted cameras, control the lighting, and test how reliably we can encode and read back color.

Why I'm building this

I want to compete in the AI race, and I don't want limited funds to be what stops me. I also want to help lower that barrier for other people. So I'm experimenting.

I've been working with color as a way to represent neural weights and inspect how information moves through a network, from encoding to decoding. The bigger question is whether color and light can physically perform useful computation beyond displaying a result calculated digitally.

In my head, I'm trying to "paint the full picture" of a neural network and put that representation to work.

So far, I've built a Rust library that stores RGBD tokens and performs exact hue arithmetic, alongside this visual walkthrough. The animation shows the idea. The docs and architecture explorer show what's actually implemented.

The hardware and software are works in progress. An enclosure may reduce ambient-light interference; it won't eliminate every source of noise. Physical neural computation, a speed or learning advantage, and a replacement for expensive GPUs are still unproven.

I'm sharing the experiment as I build it. I want to find out where it works, where it falls apart, and whether there's something useful here that others can build on.
